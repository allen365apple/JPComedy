# 共享詞庫與密碼編輯部署（管理員用）

## 架構與啟用狀態

- 翻譯工具：`allen365apple/owarai-grillmaster`，保留原始 fork 關係。
- 資料來源：`allen365apple/jpcomedy-glossary` 的 `main/glossary.json`。
- 網頁：本專案 `glossary_ui/static/`，由 GitHub Pages 發布。
- 登入／寫入：`glossary_cloud/`，部署至 Cloudflare Workers。

目前前端已連到 `https://jpcomedy-glossary.allen365apple.workers.dev`。訪客可以讀取、編輯畫面草稿、匯出和提供建議；管理員完成下方設定後，輸入共用密碼即可保存。

採用 GitHub JSON 作為小型共用資料庫，每次修改是一筆 commit。不存在另外一份需要雙向同步的 SQL 資料庫。

## 1. GitHub App（一次設定，只有管理員需要）

在 GitHub Settings → Developer settings → GitHub Apps 建立 App：

- Homepage：詞庫 GitHub Pages 網址。
- 不需要設定 OAuth callback；夥伴不會用 GitHub 登入。
- Repository permissions：**Contents: Read and write**，Metadata: Read。
- 不啟用 webhook（本版本未使用）。
- 安裝到 **Only select repositories → jpcomedy-glossary**，不要授權所有 repositories。
- Worker 使用 App installation token 寫入詞庫；夥伴只會輸入共用密碼，不需要成為 GitHub repository 協作者。

記下 App ID、Installation ID；產生 private key，均只保存在本機安全位置或 Worker secrets，不要提交至 Git。Client ID、Client secret 和 OAuth callback 在密碼版不需要。

參考：[GitHub App installation 認證](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/authenticating-as-a-github-app-installation)。

## 2. 部署後端

確認 Cloudflare 帳號方案與額度；若需要付費，先由擁有者同意，不要自動升級。

```bash
cd glossary_cloud
npm ci
npx wrangler login
npx wrangler secret put GH_APP_ID
npx wrangler secret put GH_INSTALLATION_ID
npx wrangler secret put GH_PRIVATE_KEY
npx wrangler secret put SESSION_SECRET
npx wrangler secret put EDITOR_PASSWORD
npx wrangler types
npm test
npm run check
npx wrangler deploy
```

`SESSION_SECRET` 使用密碼管理器生成至少 32 字元的隨機值。`GH_PRIVATE_KEY` 可透過安全檔案 stdin 輸入，例如 `npx wrangler secret put GH_PRIVATE_KEY < /完整路徑/private-key.pem`；不要把金鑰貼進聊天、README 或 shell 參數。

`EDITOR_PASSWORD` 就是夥伴在詞庫網頁輸入的共用密碼。密碼不放在 `wrangler.jsonc`、HTML 或 GitHub；使用 `npx wrangler secret put EDITOR_PASSWORD` 後，在隱藏輸入提示中貼上，再按 Enter。

GitHub App 必須真的安裝到詞庫 repository，且若資料分支啟用了保護規則，需明確允許這個 App 寫入或改用 PR 流程。不要為了通過測試廣泛解除保護。

## 3. 管理誰能編輯

目前採用「知道共用密碼的人可以編輯」的簡單模式，適合小型漫才夥伴群組。若未來人數變多，再升級成每人獨立帳號或 GitHub OAuth。

## 4. 啟用前端

`glossary_ui/static/cloud-config.js` 已設定為部署成功的 HTTPS Worker 網址。GitHub Pages 設定選擇 GitHub Actions。

編輯者輸入密碼後，Worker 只回傳短期簽章 session；session 只存在目前分頁的記憶體，不儲存在 localStorage，也不放進網址。重新整理後要再輸入密碼。

上線驗收：

1. `/health` 顯示 `editorConfigured: true`；這只代表配置存在，不代表 GitHub App 金鑰一定有效。
2. 訪客能讀取詞庫，但直接呼叫 PUT 也不能寫入。
3. 編輯者輸入共用密碼，保存測試詞條，GitHub 出現一筆可追溯 commit。
4. 錯誤密碼和沒有 session 的請求不能保存。
5. 兩個分頁同時開啟：第一個保存後，第二個舊版保存應收到 409，保留畫面草稿。
6. 新影片採用新 commit；舊影片仍使用自己快照；斷網會清楚回報備援來源。

## 安全與限制

- GitHub Pages 只部署靜態介面，不發布 `.env`、音檔、影片、私人轉錄和本機清理工具。
- 後端固定 repository、分支及 `glossary.json` 路徑，瀏覽器不能指定任意寫入目標。
- 共用密碼只存在 Worker Secret；儲存使用短期簽章 session、Origin 檢查和 GitHub App installation token。
- GitHub file SHA 用於防止兩人覆寫，Git 歷史提供回復依據。
- 目前不支援即時多人共同編輯，修改後需按保存；這對小型詞庫維護比較容易理解與追蹤。
- 後端有請求大小及時間限制；正式擴大使用前，依帳號方案設定額度提醒與濫用防護。
