# 共享詞庫與登入部署（管理員用）

## 架構與啟用狀態

- 翻譯工具：`allen365apple/owarai-grillmaster`，保留原始 fork 關係。
- 資料來源：`allen365apple/jpcomedy-glossary` 的 `main/glossary.json`。
- 網頁：本專案 `glossary_ui/static/`，由 GitHub Pages 發布。
- 登入／寫入：`glossary_cloud/`，部署至 Cloudflare Workers。

目前 `cloud-config.js` 的 `apiBase` 為空，網站使用公開詞庫，支援搜尋、編輯草稿、匯出、提供建議。**完成下方設定並驗收後，才把 `apiBase` 填上並宣布開放登入儲存。**

採用 GitHub JSON 作為小型共用資料庫，每次修改是一筆 commit。不存在另外一份需要雙向同步的 SQL 資料庫。

## 1. GitHub App（一次設定）

在 GitHub Settings → Developer settings → GitHub Apps 建立 App：

- Homepage：詞庫 GitHub Pages 網址。
- Callback：`https://你的-worker.workers.dev/auth/callback`。
- Repository permissions：**Contents: Read and write**，Metadata: Read。
- 不啟用 webhook（本版本未使用）。
- 安裝到 **Only select repositories → jpcomedy-glossary**，不要授權所有 repositories。
- 編輯者用 GitHub 授權登入；保存時由 App installation token 寫入，不需要把每位編輯者變成程式碼 repository 的協作者。

記下 App ID、Client ID、Installation ID；產生 Client secret 和 private key，均只保存在本機安全位置或 Worker secrets，不要提交至 Git。

參考：[GitHub App 安装認證](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/authenticating-as-a-github-app-installation)、[使用者登入](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/generating-a-user-access-token-for-a-github-app)。

## 2. 部署後端

確認 Cloudflare 帳號方案與額度；若需要付費，先由擁有者同意，不要自動升級。

```bash
cd glossary_cloud
npm ci
npx wrangler login
npx wrangler secret put GH_CLIENT_ID
npx wrangler secret put GH_CLIENT_SECRET
npx wrangler secret put GH_APP_ID
npx wrangler secret put GH_INSTALLATION_ID
npx wrangler secret put GH_PRIVATE_KEY
npx wrangler secret put SESSION_SECRET
npx wrangler types
npm test
npm run check
npx wrangler deploy
```

`SESSION_SECRET` 使用密碼管理器生成至少 32 字元的隨機值。`GH_PRIVATE_KEY` 可透過安全檔案 stdin 輸入，例如 `npx wrangler secret put GH_PRIVATE_KEY < /完整路徑/private-key.pem`；不要把金鑰貼進聊天、README 或 shell 參數。

GitHub App 必須真的安裝到詞庫 repository，且若資料分支啟用了保護規則，需明確允許這個 App 寫入或改用 PR 流程。不要為了通過測試廣泛解除保護。

## 3. 管理誰能編輯

在 `wrangler.jsonc` 的 `ALLOWED_USER_IDS` 放 GitHub 數字 ID，以逗號分隔。預設只有管理員帳號的 ID。

```bash
gh api users/夥伴帳號 --jq .id
```

使用數字 ID，避免帳號改名或舊名稱被他人註冊造成誤授權。名單由後端檢查；隱藏儲存按鈕並不是權限控管。修改名單後重新部署，已登入但被移出名單的人也無法再寫入。

每次儲存記錄 GitHub login／數字 ID；請先讓參與者知道這些資料會出現在公開的版本紀錄。若不希望公開名單，可改用同名 Worker secret，不要同時在 vars 保留該值。

## 4. 啟用前端

把 `glossary_ui/static/cloud-config.js` 的 `apiBase` 改成部署成功的 HTTPS Worker 網址（結尾不要斜線），更新後 push。GitHub Pages 設定選擇 GitHub Actions。

登入以彈出視窗進行，需允許本站彈出視窗；成功後的短期登入資訊只在記憶體中，不儲存在 localStorage，也不把 token 放入網址。重新整理後需再登入。

上線驗收：

1. `/health` 顯示 `loginConfigured: true`；這只代表配置存在，不代表金鑰一定有效。
2. 訪客能讀取詞庫，但直接呼叫 PUT 也不能寫入。
3. 管理員可完成 OAuth，保存測試詞條，GitHub 出現一筆可追溯 commit。
4. 未授權帳號不能保存；移除名單後的既有 session 也不能保存。
5. 兩個分頁同時開啟：第一個保存後，第二個舊版保存應收到 409，保留畫面草稿。
6. 新影片採用新 commit；舊影片仍使用自己快照；斷網會清楚回報備援來源。

## 安全與限制

- GitHub Pages 只部署靜態介面，不發布 `.env`、音檔、影片、私人轉錄和本機清理工具。
- 後端固定 repository、分支及 `glossary.json` 路徑，瀏覽器不能指定任意寫入目標。
- OAuth 使用有期限的簽章 state + HttpOnly cookie；儲存使用短期簽章 session、白名單和 Origin 檢查。
- GitHub file SHA 用於防止兩人覆寫，Git 歷史提供回復依據。
- 目前不支援即時多人共同編輯，修改後需按保存；這對小型詞庫維護比較容易理解與追蹤。
- 後端有請求大小及時間限制；正式擴大使用前，依帳號方案設定額度提醒與濫用防護。
